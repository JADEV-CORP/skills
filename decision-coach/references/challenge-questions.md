# Challenge Questions: 8 Scenarios

Pointed questions organized by scenario. Each question references a specific framework and source book. Use 3 to 5 questions per challenge: pick the sharpest ones for the specific situation.

---

## 1. Email challenges

1. **Clear ask in one sentence?** Can the recipient identify the exact action needed without scrolling? One email = one ask. (Krug: cognitive load)
2. **Hook in the first line?** The preview pane shows 40-80 characters. Does your opening create urgency, curiosity, or a direct benefit? (StoryBrand: hero problem + hook-structures.md)
3. **Leading with the ask or burying it?** If the ask is in paragraph 3, most recipients won't reach it. State it in the first 2 sentences. (Challenger Sale: take control)
4. **Authority demonstrated or permission requested?** "I think we should consider..." vs "Here's what I'd do." Leaders direct; subordinates suggest. (Cialdini: authority)
5. **Implication of inaction stated?** "If we don't decide by Friday, we lose the slot" creates urgency. Without it, the email can be safely ignored. (SPIN: implication question)
6. **Social proof present?** "Three other teams have already adopted this" outweighs any amount of logical argument. (Cialdini: social proof)
7. **Sounds like you or like a template?** Read it aloud. Would you actually say this to the person? If not, rewrite. (Cialdini: liking)

## 2. Business strategy challenges

1. **Hedgehog Concept defined?** Can you state the intersection of passion, best-in-world capability, and economic engine in one sentence? If not, your strategy is unfocused. (Collins: Good to Great)
2. **0-to-1 or 1-to-n?** Is this genuinely new, or a slightly better version of what exists? If 1-to-n, what is the 10x advantage that prevents a race to the bottom? (Thiel: Zero to One)
3. **Flywheel drawn?** Can you connect each step to the next, where each turn feeds the subsequent one? If the steps are independent, you have a project list, not a flywheel. (Collins: Good to Great)
4. **Smallest viable audience named?** Can you describe the SVA by industry, company size, title, pain point, and willingness to pay? "Everyone" is not a strategy. (Godin: This Is Marketing)
5. **BATNA identified?** What happens if this strategy fails? What is the fallback? Knowing your BATNA prevents desperation moves. (Fisher & Ury: Getting to Yes)
6. **Wartime or peacetime?** Are you optimizing (peacetime) or surviving (wartime)? Peacetime behaviors in wartime (consensus-seeking, long cycles, over-analysis) are lethal. (Horowitz: Hard Thing)
7. **Contrarian secret?** What truth do you believe that most competitors do not? If your thesis is consensus, the margin is already competed away. (Thiel: Zero to One)
8. **Unit economics calculated?** What is the revenue per X that drives the economic engine? If you can not state it, you don't understand the business model. (Collins: Hedgehog + Berman: Financial Intelligence)

## 3. SaaS PRD challenges

1. **Bounded context identified?** Does this feature belong to a clearly named domain? Or are you cramming it into an existing service because it is convenient? (Evans: DDD)
2. **Top 3 architecture characteristics?** What are the non-negotiable -ilities (scalability, availability, security, performance)? If you picked more than 3, you picked none. (Richards & Ford: Fundamentals of SA)
3. **Build-Measure-Learn hypothesis stated?** "We believe [change] will result in [outcome] measured by [metric]." Without this sentence, you are building features, not testing assumptions. (Ries: Lean Startup)
4. **Need-payoff question written?** Can you phrase the value from the user's perspective: "How would it help if you could [outcome]?" This is the real user story. (Rackham: SPIN Selling)
5. **MVP scope with explicit cut list?** What is in, and more importantly, what is cut? If nothing is cut, this is not an MVP. It is a waterfall spec. (Ries: Lean Startup)
6. **Conceptual model validated?** Does the user's mental model match the system model? If the user thinks "saving" means "published" but the system means "draft," confusion is baked in. (Norman: Design of Everyday Things)
7. **Trunk test passed?** Drop into the key screen cold. Can you tell: where you are, what you can do, and where to go next? 5 seconds max. (Krug: Don't Make Me Think)
8. **Pre-mortem done?** Imagine this feature shipped and failed. Why? The top 3 reasons are your real risks. (Product Strategy)

## 4. Business model challenges

1. **Economic engine defined?** What is the revenue per X that drives profit? Revenue per user, per transaction, per seat, per API call? If ambiguous, the model is ambiguous. (Collins: Good to Great)
2. **Margin of safety calculated?** What if revenue is 40% lower than projected? Does the model still survive? Plans that require perfection are fragile. (Graham: Intelligent Investor)
3. **Monopoly or competition?** Are you building a monopoly (10x better at one thing) or competing (slightly better at many things)? Competition destroys margins. (Thiel: Zero to One)
4. **Flywheel drawn?** Can each step in the business model feed the next? User pays -> revenue funds development -> better product -> more users -> user pays. (Collins: Good to Great)
5. **Cash flow profile mapped?** When does cash come in vs go out? Even profitable businesses die from cash timing mismatches. (Berman: Financial Intelligence)
6. **SVA defined precisely?** Industry, company size, job title, pain point, willingness to pay. All five. Anything less is a wish, not a target. (Godin: This Is Marketing)
7. **LTV/CAC ratio calculated?** LTV > 3x CAC is healthy. Below that, growth costs more than it earns. This one number predicts SaaS viability. (Ries: Innovation Accounting)
8. **Pricing anchored?** Are you using decoy pricing (3 tiers where the middle is the target)? Is the full-price option presented first? (Cialdini: Influence + Ross: Predictable Revenue)

## 5. Speech and presentation challenges

1. **Hero identified correctly?** The hero is the audience, not you. If the opening slide is "About Us," the hero is wrong. (Miller: Building a StoryBrand)
2. **Villain named?** Every story needs an antagonist: the competitor, the status quo, the outdated process, the wasted budget. Name it. (Miller: Building a StoryBrand)
3. **Tension defined?** What is the gap between the audience's current state and the possible better state? No gap = no reason to listen. (Godin: This Is Marketing)
4. **Lead Cialdini principle chosen?** Which of the 6 principles is your primary persuasion lever? Trying to use all 6 dilutes all of them. (Cialdini: Influence)
5. **Unexpected reframe in first 90 seconds?** What surprises the audience? A counterintuitive stat, a contrarian claim, a story that subverts expectations. Without surprise, attention dies. (Heath: Made to Stick)
6. **Specific, time-bound CTA?** "Let's schedule a 30-minute call this week" beats "Let's stay in touch." Vague CTAs get vague responses. (Miller: Building a StoryBrand)
7. **SUCCESs checklist passed?** Simple, Unexpected, Concrete, Credible, Emotional, Story. Which one is weakest in your presentation? Fix that one. (Heath: Made to Stick)

## 6. Client acquisition and negotiation challenges

1. **Teach-Tailor-Take plan prepared?** What new insight will the prospect learn? How is it tailored to their specific situation? Where will you take control of the next step? (Dixon: Challenger Sale)
2. **Three calibrated "How" questions ready?** "How would you like me to proceed?" "How does this fit with your timeline?" "How do we make this work for both sides?" (Voss: Never Split the Difference)
3. **Both BATNAs identified?** What is your walk-away alternative? What is theirs? The side with the stronger BATNA has more power. (Fisher & Ury: Getting to Yes)
4. **Emotion labeled?** "It sounds like you are concerned about the timeline." Labeling defuses tension and shows you are listening. (Voss: Never Split the Difference)
5. **Ackerman plan set?** 65% -> 85% -> 95% -> 100% of target with decreasing increments. Plus a non-monetary item at the end. (Voss: Never Split the Difference)
6. **Reciprocity play identified?** What free value can you give before asking for anything? A technical audit, a prototype, a market analysis. (Cialdini: Influence)
7. **Genuine scarcity surfaced?** "We have capacity for one more client this quarter": is it true? Real scarcity accelerates; fake scarcity destroys trust. (Cialdini: Influence)
8. **Competing on value or price?** If the conversation is about discounts, you have lost control. Redirect to value: cost of inaction, ROI, time saved. (Thiel: Zero to One + Dixon: Challenger Sale)

## 7. Technical roadmap challenges

1. **Fitness functions defined?** How will you automatically verify that architecture characteristics (performance, security, modularity) are maintained over time? Without them, drift is invisible. (Richards & Ford: Fundamentals of SA)
2. **Modularity trend: coupling up or down?** Is each change making the system more modular or more tangled? Track connascence over time. (Richards & Ford: Fundamentals of SA)
3. **Read/write workload pattern identified?** This determines everything: storage engine, caching strategy, replication topology, partitioning scheme. (Kleppmann: DDIA)
4. **Dependency direction verified?** Draw the arrows. Do they all point inward (toward domain logic)? Any outward arrow is a Dependency Rule violation. (Martin: Clean Architecture)
5. **Bounded contexts mapped?** Are service boundaries aligned with business domains? If two services share a database table, they are not separate services. (Evans: DDD + Newman: Building Microservices)
6. **Saga strategy chosen?** For distributed transactions: choreography (event-driven, decoupled) or orchestration (central coordinator, explicit flow)? Each has different failure modes. (Richardson: Microservices Patterns)
7. **Replication strategy justified?** Leader-follower, multi-leader, or leaderless? The choice depends on consistency requirements, geographic distribution, and write patterns. (Kleppmann: DDIA)
8. **Index strategy audited?** Run EXPLAIN on the top 10 queries. How many do full table scans? That number is your optimization backlog. (Schwartz: High Performance MySQL)

## 8. Code review and architecture challenges

1. **Dependency Rule followed?** Does domain logic depend on infrastructure, or vice versa? If the domain imports from the web framework, the Dependency Rule is broken. (Martin: Clean Architecture)
2. **Single Responsibility statable?** Can you state what this class does in one sentence without "and"? If not, split it. (Martin: Clean Code / SOLID)
3. **Builder pattern used for complex construction?** More than 3 constructor parameters? Telescoping constructors are a readability nightmare. (Bloch: Effective Java)
4. **Thread safety verified?** Is shared mutable state accessed from multiple threads? Where is the synchronization? "It will probably be fine" is not analysis. (Goetz: Java Concurrency in Practice)
5. **Nullable reference types handled?** Is NRT enabled? Are null checks in the right places? Every unhandled null is a future NullReferenceException. (Skeet: C# in Depth)
6. **Async/await correctness?** Any .Result or .Wait() calls? Any missing ConfigureAwait(false) in library code? Any Task.Run for I/O operations? Each one is a potential deadlock or thread-pool starvation. (Skeet: C# in Depth + Richter: CLR via C#)
7. **EXPLAIN run on new queries?** New queries without EXPLAIN are optimism, not engineering. Check the execution plan. (Schwartz: High Performance MySQL)
8. **Anemic domain model check?** Are domain objects data bags with no behavior (only getters/setters)? Business logic should live in the domain, not in service classes. (Evans: DDD + Martin: Clean Architecture)
